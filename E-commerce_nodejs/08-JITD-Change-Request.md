## 3. เปลี่ยนโดเมน

**ข้อจำกัด:** ชื่อโดเมนมีช่องว่างไม่ได้ และตัวพิมพ์ใหญ่จะถูกแปลงเป็นตัวเล็กอยู่แล้ว ดังนั้น `JITD eCommerce.onrender.com` ใช้ไม่ได้ ต้องเปลี่ยนเป็น **`jitd-ecommerce.onrender.com`**

**วิธีทำ:** เท่าที่ทราบ subdomain `.onrender.com` ถูกกำหนดตอนสร้าง service และการเปลี่ยนชื่อ service ภายหลังไม่ได้เปลี่ยน URL ตาม (ต้องเช็คกับ Render อีกทีตอนลงมือ) จึงต้องสร้าง service ใหม่:

1. สร้าง web service ใหม่ชื่อ `jitd-ecommerce` (build/start command เหมือน `chakkrit-ecommerce-web`) ถ้าชื่อนี้ถูกใช้ไปแล้ว Render จะเติมตัวอักษรต่อท้าย ต้องเช็ค URL ที่ได้จริง
2. จะเปลี่ยน API ด้วยก็ได้ (ไม่บังคับ) โดยสร้างเป็น `jitd-ecommerce-api`
3. อัปเดต env ให้ชี้กันถูกต้อง: ฝั่ง API ตั้ง `WEB_HOST=jitd-ecommerce.onrender.com` ส่วนฝั่งเว็บตั้ง `API_URL` และ `API_HOST` ไปที่ URL ของ API
4. ทดสอบให้ผ่านทั้งหมดก่อน แล้วค่อยลบ service เดิม (`chakkrit-ecommerce-web` และตัว API เดิมถ้าย้ายไปแล้ว)
5. อัปเดต `render.yaml` ให้ใช้ชื่อใหม่ด้วย

**ทางเลือก:** ถ้าอยากได้ชื่อที่สวยกว่านี้ เช่น `jitd-ecommerce.com` ให้ซื้อโดเมนเองแล้วผูกเป็น Custom Domain บน Render ได้ (free tier ก็ใช้ได้ และได้ HTTPS ฟรี)

## 5. ภาษาไทย 100% (รวมวันที่และเวลา)

**ตอนนี้:** มีพจนานุกรม en/th แค่ข้อความหลัก (store `dict` ใน `apps/web/lib/store.ts`) แต่ข้อความส่วนใหญ่ยังเขียนเป็นภาษาอังกฤษฝังในโค้ด เช่น `'Postal code is required'`, `'Coupon code'` ข้อมูล seed ทั้งหมดเป็นภาษาอังกฤษ และสกุลเงินหลักเป็น USD (ทศนิยม 3 ตำแหน่ง)

**ขอบเขตที่ต้องแปล (ต้องครบทุกข้อ):**
- หน้าร้าน: Top bar, Header, เมนู, ช่องค้นหา, หมวดหมู่, หน้าแรก, รายการสินค้า, ตัวกรองและการเรียง, หน้าสินค้า, รีวิว, ตะกร้า, คูปอง, Checkout, สั่งซื้อสำเร็จ, เปรียบเทียบ, Wishlist, บัญชีผู้ใช้, ล็อกอินและสมัครสมาชิก, Contact, Footer, หน้า 404 และ toast แจ้งเตือนทุกอัน
- หลังร้าน (`/admin`): Dashboard, สินค้า, ออเดอร์, ลูกค้า, รีวิว, คูปอง, ตั้งค่าหน้าแรก ทั้งเมนู ปุ่ม หัวตาราง สถานะ และกราฟ
- ข้อความ error ที่ส่งมาจาก API: ข้อความจาก Zod validator ใน `apps/api/src/validators` และข้อความ error จาก route หรือ middleware ต่าง ๆ
- ข้อมูล seed: ชื่อและรายละเอียดสินค้า หมวดหมู่ แบรนด์ (ถ้าเป็นชื่อแบรนด์จริงให้คงไว้) ข้อความบน Slider/Banner/Flash sale หน้า CMS และข้อความของสถานะออเดอร์
- SEO: `<html lang="th">`, title/description และ schema.org ให้เป็นภาษาไทย
- ฟอนต์: ใช้ฟอนต์ที่อ่านภาษาไทยได้ดี เช่น Noto Sans Thai, Sarabun หรือ Prompt ผ่าน `next/font/google`

**วันที่และเวลา:**
- ใช้ `Intl.DateTimeFormat('th-TH', { timeZone: 'Asia/Bangkok' })` ทุกจุด ปีจะออกมาเป็น พ.ศ. อัตโนมัติ เช่น "24 ก.ย. 2569 13:45 น."
- ต้องกำหนด timezone `Asia/Bangkok` ให้ชัดเจน เพราะเซิร์ฟเวอร์ Render ทำงานบนเวลา UTC ถ้าไม่ตั้งไว้ เวลาจะเพี้ยนไป 7 ชั่วโมง
- ตัวนับเวลาถอยหลังของ Flash sale ให้แสดงเป็น "วัน ชม. นาที วินาที"

**สกุลเงิน:** เปลี่ยน `system_default_currency` เป็น THB (฿, ทศนิยม 2 ตำแหน่ง) และตั้งราคา seed เป็นบาทโดยตรง

**ตัวเลือกภาษา:** ถ้าต้องการไทย 100% ให้ซ่อนปุ่มสลับภาษา EN หรือตั้ง `th` เป็นค่าเริ่มต้นแบบตายตัว

**เกณฑ์ตรวจรับ:** เดินดูทุกหน้าทั้งหน้าร้านและ admin แล้วต้องไม่เจอข้อความภาษาอังกฤษเลย ยกเว้นชื่อแบรนด์หรือรุ่นสินค้าที่เป็นภาษาอังกฤษโดยธรรมชาติ

## 6. ช่องทางชำระเงิน (โหมดสาธิต)

**ตอนนี้:** มีแค่เก็บเงินปลายทาง (COD) และ checkout ส่ง `paymentType: 'cod'` แบบ hardcode (`apps/web/app/(shop)/checkout/page.tsx` บรรทัด 54) ส่วน schema มี `Order.paymentType`, `paymentStatus`, `paymentDetails` และตาราง `Payment` อยู่แล้ว

**ช่องทางที่ต้องมีในหน้า Checkout:**

| ช่องทาง | การทำงานในเวอร์ชันนี้ |
|---|---|
| **QR พร้อมเพย์ (PromptPay)** | สร้าง QR ตามยอดสั่งซื้อจริงด้วย `promptpay-qr` + `qrcode` แสดงบนหน้าสั่งซื้อสำเร็จพร้อมเวลานับถอยหลังให้ชำระ แล้วให้ลูกค้าอัปโหลดสลิป |
| โอนผ่านบัญชีธนาคาร | แสดงเลขบัญชี (ข้อมูลสาธิต) ให้ลูกค้าอัปโหลดสลิป |
| บัตรเครดิต/เดบิต | แสดงฟอร์มแต่ปิดไว้ ขึ้นป้าย "เร็ว ๆ นี้" (อนาคตเชื่อม Omise หรือ Stripe) |
| TrueMoney Wallet | แสดงตัวเลือกแต่ปิดไว้ ขึ้นป้าย "เร็ว ๆ นี้" |
| Mobile Banking (K PLUS, SCB Easy ฯลฯ) | แสดงตัวเลือกแต่ปิดไว้ ขึ้นป้าย "เร็ว ๆ นี้" |
| เก็บเงินปลายทาง (COD) | ใช้งานได้เหมือนเดิม |

**สำคัญ: เรื่องความชัดเจนกับลูกค้า**
- ทุกช่องทางที่ยังไม่ตัดเงินจริงต้องมีป้าย **"โหมดทดสอบ — ยังไม่มีการเรียกเก็บเงินจริง"** ให้เห็นชัด
- QR พร้อมเพย์: ถ้าใส่เบอร์หรือเลขพร้อมเพย์จริงลงไป QR จะโอนเงินเข้าบัญชีได้จริงทันที แต่ระบบยังยืนยันยอดอัตโนมัติไม่ได้ ช่วงสาธิตจึงควรใช้เลขพร้อมเพย์สาธิต หรือถ้าจะใช้เลขจริง ต้องให้แอดมินตรวจสลิปด้วยตัวเอง และต้องแจ้งลูกค้าให้ชัดเจน

**งานฝั่ง API:**
- เพิ่มค่า `paymentType` ที่ Zod ยอมรับ: `promptpay`, `bank_transfer`, `card`, `truemoney`, `mobile_banking`, `cod` และให้ API ปฏิเสธช่องทางที่ยังปิดอยู่
- เพิ่มสถานะ "รอตรวจสอบการชำระเงิน" (เช่น `pending_verification` ใน enum `PaymentStatus`)
- Endpoint อัปโหลดสลิป (ใช้ multer และตรวจ magic bytes แบบเดียวกับอัปโหลดรูปสินค้า) แล้วบันทึกลงตาราง `Payment`
- Endpoint `GET /api/orders/:code/promptpay-qr` สำหรับสร้าง QR จากยอดที่คำนวณฝั่ง server
- ตั้งค่าใน `businessSetting`: `promptpay_id`, `bank_accounts`, และรายการช่องทางที่เปิด/ปิด

**งานฝั่งเว็บ:**
- เพิ่มตัวเลือกช่องทางชำระเงินใน Checkout (radio พร้อมไอคอน)
- หน้าสั่งซื้อสำเร็จแสดง QR หรือเลขบัญชี พร้อมปุ่มอัปโหลดสลิป
- หน้าออเดอร์ของลูกค้าแสดงสถานะการชำระเงิน
- Admin: ดูสลิป กด "ยืนยันชำระแล้ว" หรือ "ปฏิเสธ" และหน้าตั้งค่าช่องทางชำระเงิน

**ข้อจำกัดบน free tier:** สลิปที่อัปโหลดจะหายทุกครั้งที่ deploy ใหม่ (ดิสก์ไม่ถาวร) เหมือนรูปสินค้าที่อัปโหลด

## ลำดับการทำงานที่แนะนำ

1. **ภาษาไทยและสกุลเงิน THB (ข้อ 5):** ทำก่อนเพราะกระทบเกือบทุกไฟล์ และทำให้ข้อความของงานถัด ๆ ไปเป็นภาษาไทยตั้งแต่แรก
2. **ชื่อเว็บและอีเมล (ข้อ 2 และ 4):** งานเล็ก ทำพร้อมกับข้อ 5 ได้เลย
3. **ช่องทางชำระเงิน (ข้อ 6):** แก้ schema → API → หน้า Checkout → Admin
